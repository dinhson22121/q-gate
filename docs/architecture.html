Từ git push tới gate verdict

Hai container Docker trên máy dev: qgate (giữ secret, gọi Claude/Jira/Figma, phục vụ dashboard) và qgate-runner (chạy code không tin cậy, không có secret). qgate theo dõi các repo được mount và review khi có git push (không review từng commit local): cả nhánh merge-base(base, head)..head được kiểm bằng check deterministic, quality gate, regression, các agent Claude và AC của ticket Jira. Kết quả, cache và config nằm trong SQLite ở /data. Sau mỗi review, qgate ghi file Markdown + qgate-rules.md cho agent của dev, và (tùy chọn) báo cáo HTML để đính kèm Jira. LLM không tự quyết định pass hay fail.

Ranh giới tin cậy

  • Repo được phép chọn: model, effort, gate, ignore, [[checks]], ac_field, danh sách project Jira.
  • Chỉ server (admin) được đặt: endpoint của Claude, Jira và Figma, lệnh MCP, webhook, watch.base_branch (env QGATE_WATCH_BASE_BRANCH; repo có thể ghi đè trong .qgate.toml). Đặt qua env/config, chỉ đọc trên UI. HTTP redirect bị tắt.
  • Dashboard cần login: token riêng của mỗi instance (docker compose exec qgate qgate login-url, cookie 30 ngày); API ghi còn cần token theo từng request.
  • Checks và test agent chạy code của repo trong container riêng qgate-runner (qua Unix socket trên volume qgate-work): không có secret, không mount /data, /config, /reviews, /repos, toolchains read-only, mạng bridge mặc định (QGATE_RUNNER_NETWORK=none = offline), cache riêng, và không có token login dashboard nên không đọc hay ghi được dashboard. Mỗi scenario test có snapshot riêng. Chỉ watch repo bạn tin tưởng.
